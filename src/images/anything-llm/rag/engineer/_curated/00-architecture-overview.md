# Архитектура NevaDWH — краткий обзор (stub для RAG)

Это **тестовый** корпус для workspace **Neva DWH Engineer**. Полный индекс SQL (`dbmssql`, `dbpsql`, `mq_ms`) будет добавлен позже.

## Слои данных

| Слой | Назначение |
|------|------------|
| **Landing** | Сырые данные из источника (1С, файлы, очереди). Минимальная очистка. |
| **ODS** | Операционный слой «дневной активности»: актуальные срезы для отчётности. |
| **DWH** | Историческое хранилище: факты, измерения, аналитика. |

Типичный поток: `источник → Landing → ODS → DWH` (через ETL / staging).

## Схемы (роли)

| Схема / зона | Роль |
|--------------|------|
| `mq` | Буферы и очереди сообщений (интеграция с MQ-сервисом) |
| `etl` | Процедуры и объекты загрузки / трансформации |
| `staging` | Промежуточные таблицы перед target |
| `target` / целевые схемы ODS/DWH | Итоговые таблицы для потребителей |

Конкретные имена процедур зависят от проекта генератора (клиентский dacpac).

## Связанные компоненты в репозитории

- SQL MS: проекты вроде `dbmssql` / шаблоны генератора
- SQL PG: `dbpsql`
- Очереди: сервис **MQ** (`mq_ms` / `MQ.WebService`) — SendMsg / GetMsg, RabbitMQ или Kafka

## Ограничение stub

Пока в индексе нет полного дампа процедур. На вопросы «разбери `odins.load_FACT_*`» отвечай: **«полного кода нет в индексе»** (stub). Опиши слой/схему по обзору или уточни имя объекта после расширения корпуса.
