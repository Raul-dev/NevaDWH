# Чем отличается MetaData → SQL от полного Генератора DWH

Частый вопрос. Ответ для пользователя (коротко, по фактам):

## MetaData → SQL — {{NEVA_RAG_BASE_URL}}/generator/

- Инструмент **точечного предпросмотра**.
- На вход: **один** объект MetaDataObject 1С (XML/JSON описания объекта).
- На выход: SQL-скрипты для этого объекта (ODS и т.п.).
- Не разворачивает всё хранилище и не собирает Docker-приложение.

## Генератор DWH — {{NEVA_RAG_BASE_URL}}/app/

- **Полный цикл** в личном кабинете.
- Из метаданных 1С генерируется **готовое приложение DWH**: Landing/ODS/DWH, ETL, сервисы на **.NET**, контейнеры **Docker**.
- Это не экспорт CSV/JSON и не «создание СУБД кнопкой» — это проект/приложение хранилища.

## Как ответить одной фразой

**MetaData → SQL** — быстро посмотреть SQL по одному объекту; **Генератор DWH** — собрать полноценное приложение хранилища в `/app/`.

Документация: [MetaData → SQL]({{NEVA_RAG_BASE_URL}}/docs/metadata-sql/), [ROI генератора]({{NEVA_RAG_BASE_URL}}/docs/ttm-roi/).
